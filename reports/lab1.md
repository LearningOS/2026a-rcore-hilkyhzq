## 3. 实现设计

### 3.1 每任务独立计数

在 `TaskControlBlock` 内增加 `BTreeMap<usize, usize>`，键为系统调用号，值为累计次数。每个任务创建时得到独立的空表；未出现过的调用号查询为零。

采用稀疏表而非为每个任务预留大数组，避免任务数组初始化时占用大量启动栈空间，也允许直接查询尚未出现过的调用号。代价是首次调用某个系统调用时需要从已初始化的内核堆中分配节点。

`TaskControlBlock` 不再是 `Copy`，任务数组用 `core::array::from_fn` 逐项初始化，保证各任务拥有自己的计数表。

### 3.2 在分发前计数

`syscall()` 在匹配调用号之前执行 `count_current_syscall(syscall_id)`。这样：

1. 当前 `sys_trace` 查询能看到它自身已经计数。
2. 不返回的 `sys_exit` 也能计数。
3. `sys_yield` 发生调度前已将次数写入原任务。

计数操作结束时释放 `UPSafeCell` 的借用，然后才进入具体系统调用，避免借用跨越调度点。加法采用饱和加法，避免计数溢出后回绕。

### 3.3 trace 请求语义

| 请求 | 实现 |
| --- | --- |
| 0 | 从 `id` 指定的地址执行 `read_volatile`，将一个无符号字节作为返回值 |
| 1 | 将 `data` 的低 8 位通过 `write_volatile` 写入 `id` 指定的地址，返回 0 |
| 2 | 返回当前任务对调用号 `id` 的累计调用次数 |
| 其他 | 返回 -1 |

本章尚未启用第四章的用户虚拟地址空间，因此读写使用直接地址。这里没有实现地址权限校验：恶意或无效指针可能引起内核异常，不能把本章实现当作生产系统中安全的用户内存接口。后续需要按用户页表逐页检查并翻译地址。

## 4. 任务切换与陷入处理

用户执行 `ecall` 后，`__alltraps` 使用 `sscratch` 交换用户栈和内核栈，在内核栈中保存 `TrapContext`，然后进入 `trap_handler`。系统调用号来自 `a7`，参数来自 `a0` 至 `a2`，返回值写回 `a0`。处理系统调用时 `sepc` 增加 4，防止返回用户态后重复执行同一条 `ecall`。

`TrapContext` 保存用户执行状态；`TaskContext` 则用于内核任务切换，保存 `ra`、`sp` 与 `s0` 至 `s11`。它们用途不同：前者支持陷入返回，后者允许内核执行流在 `__switch` 后恢复。

主动调用 `yield` 与时钟中断都可以使当前任务变为 Ready，调度器按现有轮转规则选择下一个 Ready 任务。退出任务标记为 Exited，不再参加调度。

## 5. 测试过程与观察

第一次使用系统自带 QEMU 6.2 时，固件输出后未进入应用，检查超时。这一结果属于环境不匹配，不能用于判断 trace 的实现。换成要求的 QEMU 8.2.2 后，原始模板得到 `5/7`，失败点为 `ch3_trace` 对 `count_syscall(SYSCALL_GETTIMEOFDAY)` 的断言，符合 trace 返回 -1 的未实现状态。

完成代码后，相同固定版本检查器给出 `7/7`，日志包含 `string from task trace test` 与 `Test trace OK`。该测试同时检查 trace 自身的累计次数、其他调用号的次数以及字节读写。两个 sleep 测试继续通过。第一次完整运行随后报告缺少 lab1 文件，因此在补齐本报告后重新运行，只有报告检查也通过、make 正常退出才视为本章完成。

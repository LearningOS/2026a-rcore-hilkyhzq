## 实现

### 用户地址与内核地址

启用页表后，用户传入的指针属于用户虚拟地址空间，内核不能再直接解引用。`checked_user_buffer` 根据当前任务的页表 token，逐页查询 PTE，检查 V、U 和读写权限，再将虚拟地址翻译成物理页与页内偏移。接口使用 checked_add 防止地址加法溢出，并只接受 SV39 低半区用户地址。

时间结构体可能跨页，因此 `sys_get_time` 将当前时间作为字节序列，分段复制到翻译后的缓冲区；不要求用户指针满足内核结构体对齐。整个范围先验证、后写入，避免第二页无效时只写入一半。

`sys_trace` 的读写请求使用同一检查接口处理一个字节；只读映射上的写入、未映射地址、内核地址均返回 -1。请求 2 继续查询各任务独立的系统调用计数，分发入口仍在执行具体调用前计数。

### mmap

检查起始地址页对齐、权限位非零且不超出 0b111、地址范围无溢出，并逐页确认没有现有有效映射。数据页分配成功后才安装映射，页面由 `FrameTracker` 管理，权限包含用户态 U 位。

课程把 R/W/X 编码为参数低三位，而 PTE 中它们位于第 1 至 3 位，因此需要左移一位。仅设置 W、不设置 R 的参数仍按课程要求接受；这种 PTE 在 RISC-V 上是保留编码，实际访问将异常，官方测试专门检查这一点。

### munmap

先确认范围内的所有页都存在且是用户页，再删除映射与物理页记录。失败时不部分修改映射。部分解除映射时，将原 MapArea 拆分为左右剩余区域，而非只清除 PTE：这样后续按区域复制地址空间时不会恢复已经解除的页面。修改后执行 `sfence.vma` 清除可能残留的地址转换。

## 关键观察

- 页号取整与范围终点向上取整很重要，长度 4097 会覆盖两页。
- 起始地址必须对齐，长度不必对齐。
- 解除映射的范围内只要有一个空洞，整个调用就失败。
- PTE 的 V 位不等于用户可访问：还必须检查 U 位与对应读写权限。
- 原有 `sbrk` 使用独立的堆区域；没有修改其基本流程。

## 独立复查后的回归修复

独立复查指出 mmap 与 sbrk 的交互会导致原有按单区域扩展/收缩堆的逻辑失效。增加了额外的用户态回归程序，先在堆顶 mmap，再尝试 sbrk 扩展，确实复现了页表重复映射的内核断言。修复后堆增长复用全范围碰撞检查，碰撞返回 -1；堆收缩会遍历所有片段并移除区间内仍存在的页，允许先前 munmap 留下的空洞。空堆描述符也保留，不因范围解除映射而丢失。回归程序进一步检查解除中间页后整体收缩、解除首个堆页后再收缩与扩展。这是额外验证，不计入官方的 16 个检查项。

额外回归运行结果：官方 16/16，额外完成标记出现，报告检查通过，检查器退出码 0。回归程序如下（可另存为用户测试程序复现）：

```rust
#![no_std]
#![no_main]

extern crate user_lib;
use user_lib::{mmap, munmap, println, sbrk, trace_read};

#[no_mangle]
fn main() -> i32 {
    let base = sbrk(0) as usize;
    assert_eq!(base % 4096, 0);
    assert_eq!(mmap(base, 4096, 3), 0);
    assert_eq!(sbrk(4096), -1);
    assert_eq!(munmap(base, 4096), 0);
    assert_eq!(sbrk(3 * 4096), base as isize);
    assert_eq!(munmap(base + 4096, 4096), 0);
    assert_eq!(sbrk(-3 * 4096), (base + 3 * 4096) as isize);
    assert_eq!(trace_read((base + 2 * 4096) as *const u8), None);
    assert_eq!(sbrk(4096), base as isize);
    assert_eq!(munmap(base, 4096), 0);
    assert_eq!(sbrk(-4096), (base + 4096) as isize);
    assert_eq!(sbrk(4096), base as isize);
    println!("Extra VM regression checks complete");
    0
}
```
